# Установка и настройка сайта

Инструкция написана для человека, который никогда не работал с кодом.
Всё, что нужно, — файловый менеджер хостинга (или FTP) и текстовый редактор.

---

## 1. Требования к хостингу

| Что нужно | Значение |
|---|---|
| PHP | 8.1 или новее (проверено на 8.4) |
| Расширения PHP | стандартные: `mbstring`, `json`, `openssl` (для SMTP) |
| База данных | **не нужна** |
| Composer, npm, Node.js, Docker | **не нужны** |
| Права на запись | только каталог `storage/` |

Подойдёт любой обычный виртуальный хостинг с PHP. Панель управления
(cPanel, ISPmanager, Plesk) — любая.

---

## 2. Куда загрузить файлы

1. Загрузите **содержимое** этой папки в корень сайта — обычно это
   `public_html`, `www` или `httpdocs`. Файл `index.php` должен оказаться
   прямо в корне, а не во вложенной папке.
2. Проверьте права: каталогу `storage` и его подпапкам нужны права на запись
   (обычно `755`, на некоторых хостингах `775`).
3. Откройте сайт в браузере. Должна открыться главная страница.

Если сайт лежит не в корне домена, а в подпапке (например, `site.ru/potolki/`),
укажите её в `config/site.php`:

```php
'base_path' => '/potolki',
```

---

## 3. Где менять свои данные

Все настройки — в папке `config`. Другие файлы трогать не нужно.

### `config/site.php` — главный файл

| Что менять | Строка |
|---|---|
| Название компании | `brand.name` |
| Домен | `site.domain` |
| Телефон | `contacts.phone.display` (как показывать) и `contacts.phone.raw` (для кнопки «позвонить», только цифры) |
| Почта | `contacts.email` |
| Куда приходят заявки | `contacts.email_leads` и `mail.to` в `config/mail.php` |
| Мессенджеры | `contacts.whatsapp`, `contacts.telegram`, `contacts.max` — `null` значит «кнопки нет» |
| Режим работы | `contacts.work_hours` |
| Адрес офиса | `contacts.office_address` — оставьте `null`, если офиса для клиентов нет |
| Реквизиты | раздел `legal` — без них юридические страницы закрыты от индексации |
| Гарантии | раздел `guarantee` — пока пусто, блоки о гарантии на сайте не показываются |
| Города и зона выезда | раздел `geo` |
| Аналитика | раздел `analytics` + `features.analytics = true` |

**Важно:** значение `null` означает «данных нет». Сайт от этого не ломается —
он просто не показывает блок. Это сделано специально, чтобы на сайте не было
выдуманных сведений.

### `config/prices.php` — цены

Все цены сайта лежат **только здесь**. Прайс-лист на сайте и калькулятор
берут числа отсюда, поэтому разойтись они не могут.

После изменения цен:

1. Поднимите версию прайса: `'version' => '2026-09-01.1'` — версия
   сохраняется вместе с заявкой, чтобы через месяц было понятно,
   по каким ценам считали клиенту.
2. Когда проверите все ставки, поставьте `'approved_by_owner' => true`.

### `config/locations/` — города и районы

Список территорий. Добавление города **не публикует** страницу автоматически:
нужно заполнить тексты и поставить `status => 'published'`, `index => true`.
Проверка не даст опубликовать пустую страницу (см. раздел 8).

После изменения списка обязательно выполните:

```
php tools/build-routes.php
```

## 4. Настройка почты

Без этого шага письма о заявках **не будут приходить**. Это не преувеличение:
по умолчанию сайт работает в режиме `log` и только записывает письма в файл.

### Вариант А (рекомендуется): SMTP

1. Заведите почтовый ящик на своём домене (например, `no-reply@ваш-домен.ru`)
   в панели хостинга.
2. Скопируйте `config/secrets.sample.php` в `config/secrets.php`
   и впишите туда логин и пароль от ящика.
3. В `config/mail.php` укажите:

```php
'transport' => 'smtp',
'from' => ['email' => 'no-reply@ваш-домен.ru', 'name' => 'Название компании'],
'to'   => ['почта@куда-приходят-заявки.ru'],
```

Обычные настройки хостингов: порт `465` + шифрование `ssl`, либо `587` + `tls`.

### Вариант Б: функция mail() хостинга

```php
'transport' => 'mail',
```

Работает не везде: многие хостинги либо блокируют `mail()`, либо письма
попадают в спам, потому что не настроены записи SPF и DKIM. Если письма
не доходят — переходите на SMTP.

### Что делать, если почта временно недоступна

Заявка не теряется: письмо сохраняется в `storage/mail-queue`.
Отправить накопившееся:

```
php tools/mail-queue.php send
```

Эту команду можно поставить в cron раз в 10 минут:

```
*/10 * * * * /usr/bin/php /путь/к/сайту/tools/mail-queue.php send >/dev/null 2>&1
```

## 5. Как проверить, что заявки приходят

1. Откройте сайт, заполните форму «Вызвать замерщика» своими данными.
2. Через минуту проверьте ящик из `mail.to` — должно прийти письмо с номером
   заявки, всеми полями и расчётом (если он был).
3. Если письма нет:
   - посмотрите `storage/logs/app-ГГГГ-ММ.log` — там строка `mail.failed`
     с причиной;
   - проверьте `storage/mail-queue` — если письмо там, проблема в SMTP;
   - при `transport => 'log'` письма лежат в `storage/logs/mail-ГГГГ-ММ-ДД.log`.

Диагностическая панель: задайте в `config/site.php`
`runtime.diag_key => 'любое-секретное-слово'` и откройте любую страницу
с `?diag=любое-секретное-слово`. Наверху появится список незаполненных данных.
Посетители его не видят.

## 5.1. Демонстрационный режим (staging)

Сейчас сайт закрыт от индексации **целиком** — так и должно быть до переноса
на рабочий домен. Отвечает за это одна строка в `config/site.php`:

```php
'runtime' => [
    'staging' => true,
],
```

Что делает режим:

| Рубеж | Что происходит |
|---|---|
| Мета-тег | на каждой странице `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet">` |
| HTTP-заголовок | `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` — работает и для файлов вне шаблонов |
| `robots.txt` | `User-agent: * / Disallow: /`, ссылки на карту сайта нет |
| `sitemap.xml` | пустой, с пояснением внутри |

Настройки отдельных страниц режим перекрывает: открыть что-то «в обход»
нельзя. Дополнительные страховки — демонстрационный домен (`example…`)
и `env = development`: при них сайт остаётся закрытым, даже если флаг снят.

### Как открыть сайт для поиска

Порядок именно такой, менять его не нужно:

1. Перенести сайт на рабочий домен и указать его в `site.domain`.
2. Заполнить обязательные данные из `DATA_REQUIRED.md` (контакты, реквизиты, прайс).
3. Настроить почту и отправить тестовую заявку (раздел 5 выше).
4. Пройти чек-лист из раздела 12.
5. Поставить `'staging' => false`.
6. Выполнить `php tools/build-routes.php` — robots.txt и sitemap.xml
   перезапишутся рабочими правилами.
7. Проверить: `curl -I https://ваш-домен/` — заголовка `X-Robots-Tag` быть не должно,
   а `/robots.txt` должен содержать строку `Sitemap:`.

После этого к индексации будут открыты 105 страниц. Остальные 147
(районы Москвы, часть городов, служебные страницы) останутся закрытыми,
пока для них не появится собственное содержание, — см. раздел 8.

## 6. Аналитика

1. Впишите номер счётчика в `config/site.php` → `analytics.yandex_metrika_id`.
2. Включите модуль: `features.analytics => true`.

Счётчик загружается **только после согласия** посетителя в cookie-баннере —
это требование к обработке данных, и обходить его не нужно.

Цели, которые отправляются автоматически: `form_*` (по типу формы),
`call_click`, `messenger_*`, `calculator_result`, `estimate_print`.
Создайте их в Метрике с такими же названиями.

---

## 7. Изображения

Положите файлы в `assets/images/` и назовите так, как указано в `IMAGE_BRIEF.md`.
Главная страница ищет `assets/images/hero.webp` — пока файла нет, на его месте
светлая заливка, а не «заглушка из фотобанка».

Формат: WebP или AVIF, ширина 1600–2400 px для крупных изображений.

---

## 8. Публикация страниц городов и районов

Порядок такой:

1. Откройте `config/locations/mo-goroda.php` (или `rajony.php`).
2. Заполните для территории: `housing` (2 и более фактов о застройке),
   `faq` (2 и более вопросов), `services` (3 и более услуг),
   `seo.lead` (собственный текст от 180 символов).
3. Поставьте `'status' => 'published'` и `'index' => true`.
4. Выполните проверку:

```
php tests/run.php geo
```

Если текст шаблонный или слишком короткий, проверка не пройдёт, а страница
останется закрытой от индексации. Это сделано намеренно: массовые страницы
с заменой одного топонима поисковые системы считают дорвеями.

5. Обновите маршруты и карту сайта:

```
php tools/build-routes.php
```

## 9. Обновление версии согласий

Если вы поменяли текст политики или согласия:

1. Отредактируйте текст в `content/legal.php`.
2. Поднимите версию и дату в `config/consent-versions.php`.

Версия сохраняется вместе с каждой заявкой — это доказательство того,
с какой именно редакцией согласился человек.

При изменении состава cookie-категорий поднимите
`consent.cookie_banner.version` — тогда у посетителей заново спросят выбор.

## 10. Какие каталоги должны быть закрыты от посетителей

`config`, `src`, `storage`, `tests`, `tools`, `includes`, `templates`, `content`.

На Apache они уже закрыты: в каждом лежит `.htaccess`, плюс правило в корневом
`.htaccess`. Ничего делать не нужно.

**На Nginx** добавьте в конфигурацию сайта:

```nginx
location ~ ^/(config|src|storage|tests|tools|includes|templates|content)/ {
    deny all;
    return 404;
}

location ~ /\.(?!well-known) {
    deny all;
}

# Чистые URL — это настоящие каталоги, поэтому достаточно обычного правила:
location / {
    try_files $uri $uri/ /404.php;
}

location = /sitemap.xml {
    try_files $uri /sitemap.php;
}

location ~ \.php$ {
    include fastcgi_params;
    fastcgi_pass unix:/run/php/php8.1-fpm.sock;   # путь уточните у хостинга
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
}
```

## 11. Что запускать после изменений

| Что изменили | Команда |
|---|---|
| Список городов, статьи, услуги, модули | `php tools/build-routes.php` |
| Цены | ничего, но поднимите `version` в прайсе |
| Домен | `php tools/build-routes.php` (обновит robots.txt и sitemap) |
| Перед публикацией сайта | `php tests/run.php` |

Если на хостинге нет доступа к командной строке, эти команды можно выполнить
на своём компьютере (PHP 8.1+) и загрузить обновлённые файлы на сервер.

## 12. Проверка перед запуском

```
php tests/run.php
```

Проверяются: расчёты калькулятора, формы и защита, юридические согласия,
уникальность мета-тегов, sitemap, качество географических страниц, целостность
ссылок и синтаксис всех файлов. Ожидаемый результат — «провалено: 0».

Дополнительно вручную:

- [ ] телефон и почта заменены на рабочие;
- [ ] в футере видны реквизиты;
- [ ] тестовая заявка дошла на почту;
- [ ] форма отправляется при выключенном JavaScript;
- [ ] cookie-баннер появляется и запоминает выбор;
- [ ] счётчик Метрики не грузится до согласия (вкладка «Сеть» в браузере);
- [ ] сайт открывается по HTTPS, редирект с HTTP включён в `.htaccess`;
- [ ] `/sitemap.xml` открывается и содержит ваш домен.

# Изображения проекта

Все изображения хранятся внутри проекта. Внешние ссылки на картинки
не используются: сайт должен открываться, даже если сторонний сервис
недоступен.

- Исходники: `assets/source/`
- Готовые варианты: `assets/img/` (собираются командой `npm run images`)

## Фон первого экрана и шапок внутренних страниц

| | |
|---|---|
| Исходник | `assets/source/hero-road-production.png`, 1672×941 |
| Происхождение | входил в переданный архив сайта |
| Где используется | `.hero` (главная), `.page-intro` (внутренние страницы) |
| Варианты | `hero-road-640`, `hero-road-960`, `hero-road-1280` в AVIF и WebP |

Исходный PNG весил 2,7 МБ и загружался на каждой странице. Телефон
теперь получает вариант шириной 640 px (около 32 КБ), десктоп — 1280 px.
Поверх фотографии лежит плотный тёмно-зелёный градиент, поэтому сжатие
с качеством 62 визуально не заметно.

## Фотография реки Оки — фон футера

| | |
|---|---|
| Исходники | `assets/source/oka-footer-desktop.png` (2172×724), `-tablet.png` (1774×887), `-mobile.png` (1122×1402) |
| **Автор** | **владелец сайта** |
| **Права** | **собственная фотография автора; публикация разрешена автором** |
| Где используется | фон `footer.site-footer` на всех страницах |
| Варианты | `oka-footer-desktop` 1920 px, `-tablet` 1200 px, `-mobile` 860 px в AVIF, WebP и JPEG (51–113 КБ) |

Снимок не из внешнего банка изображений: его передал владелец сайта
и подтвердил своё авторство и разрешение на публикацию. Поэтому ссылка
на страницу первоисточника и название публичной лицензии здесь
неприменимы — правами распоряжается сам автор.

Три кадра подготовлены автором под форму футера на каждом экране:
широкая полоса 3:1 на компьютере, 2:1 на планшете и вертикальный
кадр 0,8:1 на телефоне. Если дать телефону широкий кадр, обрезка
по заполнению съест бока и излучина уйдёт из вида. Кадрирование
автора при сжатии не изменялось — файлы только переведены
в лёгкие форматы.

Фотография — именно фон футера, а не отдельная полоса над ним:
название партнёрства, меню и правовые ссылки лежат прямо поверх
снимка. Читаемость обеспечивает тёмно-зелёный градиент между
фотографией и текстом, снизу более плотный. Подписи под фотографией нет.

Как это устроено в разметке и стилях (раздел 10 в `assets/site.css`):

- `<picture class="footer-bg">` и `<img>` внутри него — `position:
  absolute; inset: 0; width: 100%; height: 100%`. Без правила
  для самого `<picture>` он остаётся строчным элементом обычного
  потока: тогда снимок встаёт отдельной картинкой над текстом
  и занимает лишь часть ширины футера — именно так футер
  и выглядел неправильно на живом сайте.
- У `.site-footer.has-photo` снимаются собственные `padding: 60px 0`
  и `border-top` из основного файла стилей: они давали зелёный кант
  и линию над фотографией.
- Высота футера — `min-height: clamp(440px, 26vw, 560px)`; открытая
  часть снимка получается за счёт верхнего отступа `.footer-inner`
  (`clamp(240px, 17vw, 340px)`).
- Затемнение — `::after` поверх фотографии, содержимое лежит выше
  него по `z-index`.

## Схема проезда на странице «Контакты»

| | |
|---|---|
| Исходник | `assets/source/contact-map.png`, 1983×793, 2,34 МБ |
| Происхождение | передана владельцем сайта готовой |
| Где используется | блок «Как нас найти» на странице `/contacts` |
| Варианты | `contact-map-900`, `contact-map-1400`, `contact-map-1980` в AVIF и WebP, исходный PNG сохранён |

География, подписи и номера участков на схеме не изменялись.

Подложка схемы — спутниковый снимок из Яндекс.Карт, на изображении
видны отметки сервиса. Условия использования картографических сервисов
обычно требуют сохранять отметку правообладателя и ограничивают
коммерческое применение. Отметки на схеме сохранены; вопрос о праве
на публикацию решает владелец сайта.

## Страницы документов для просмотра на телефоне

| | |
|---|---|
| Исходники | `documents/files/*.pdf` — уже опубликованные документы |
| Где используется | окно «Посмотреть» в разделе `/documents` на телефонах и планшетах |
| Результат | `documents/pages/<имя>/01.webp`, `02.webp`, … и `pages.json` |
| Команда | `npm run documents:pages` |

Мобильные браузеры не показывают PDF внутри страницы: Chrome для
Android вместо документа отдаёт файл в загрузки. Из-за этого на
телефоне кнопка «Посмотреть» не работала — оставалось только
«Скачать». Поэтому каждая страница документа заранее переводится
в картинку, и телефон листает документ прямо в окне.

Устав — 24 страницы в оттенках серого, около 144 КБ каждая;
свидетельство ЕГРЮЛ — одна цветная страница, 130 КБ. Ширина 1000 px:
машинописный текст скана читается полностью. Второго набора в JPEG
нет — он удвоил бы вес каталога ради браузеров старше 2020 года;
для них в окне остаётся «Скачать», а скрипт покажет пояснение,
если картинка не загрузилась.

Страницы грузятся по мере пролистывания (`loading="lazy"`), поэтому
открытие Устава стоит одной страницы, а не всего документа.

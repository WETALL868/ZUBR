# Аналитика корпоративной почты

Локальная программа для ежедневного контроля обработки клиентской переписки в
Яндекс.Почте. Отвечает на главный вопрос:

> **Какие клиенты не получили то, что запрашивали?**

Особо выделяются две ситуации:

* **ПРОЧИТАНО, НО НЕ ОТВЕЧЕНО** — письмо клиента открыли, но ответа нет;
* **ОТВЕТ ОТПРАВЛЕН, НО ЗАПРОС КЛИЕНТА НЕ ВЫПОЛНЕН** — менеджер ответил, но клиент
  не получил то, что просил (например, просил счёт, а ему сообщили только цену).

## 1. Что делает программа

* Подключается к Яндекс.Почте по IMAP **в режиме только для чтения**.
* Загружает письма за выбранный период в локальную базу SQLite.
* Собирает письма в цепочки — каждая цепочка считается одним клиентским обращением.
* Определяет, кто написал: клиент или сотрудник компании.
* Отделяет рассылки, автоматические уведомления и спам от клиентской переписки.
* **Разбивает обращение клиента на отдельные задачи.** Письмо «сообщите цену,
  наличие, срок и выставите счёт с доставкой до Красноярска» превращается в пять
  задач, каждая проверяется отдельно.
* Проверяет по каждой задаче, получил ли клиент результат:
  счёт — приложен ли файл счёта; цена — названа ли конкретная сумма;
  срок — указан ли конкретный срок; аналог — предложена ли конкретная модель.
* Присваивает обращению статус и **всегда объясняет причину** статуса.
* Показывает рекомендуемое следующее действие.
* Считает время ожидания ответа: фактическое и в рабочих часах.
* Выделяет прочитанные письма без ответа и повторные обращения клиентов.
* Формирует ежедневный отчёт, статистику по менеджерам и типам запросов.
* Экспортирует данные в Excel и HTML.
* Позволяет вручную исправить любое решение программы — с сохранением в истории.

## 2. Что программа пока не делает

* Не отправляет письма и не создаёт черновики.
* Не удаляет, не перемещает письма, не меняет папки.
* Не отмечает письма прочитанными, не ставит флаги и метки.
* Не формирует счета и коммерческие предложения.
* Не читает содержимое вложений (анализируются имя, тип и размер файла).
* Не интегрируется с 1С и другими учётными системами.
* Не работает по расписанию — синхронизация запускается пользователем.

## 4. Установка Python

**Windows**

1. Откройте https://www.python.org/downloads/
2. Скачайте Python 3.12 или новее.
3. Запустите установщик и **обязательно отметьте галочку «Add Python to PATH»**.
4. Нажмите «Install Now».
5. Проверьте установку: откройте «Командную строку» и выполните `python --version`.

**macOS / Linux**

```bash
python3 --version    # проверить текущую версию
# при необходимости: brew install python@3.12   (macOS)
#                    sudo apt install python3.12 python3.12-venv   (Ubuntu)
```

## 5. Настройка Яндекс.Почты

Доступ по IMAP должен быть разрешён:

1. Войдите в Яндекс.Почту через браузер.
2. Откройте **Настройки → Почтовые программы**.
3. Включите **«Разрешить доступ к почтовому ящику с помощью почтовых клиентов»**
   и протокол **IMAP**.
4. Сохраните изменения.

> Для корпоративной почты на Яндекс 360 доступ по IMAP может быть закрыт
> администратором организации — в этом случае обратитесь к нему.

## 6. Создание пароля приложения

Основной пароль от аккаунта использовать **нельзя** — Яндекс его не примет.

1. Откройте https://id.yandex.ru
2. Раздел **Безопасность → Пароли приложений**.
3. Выберите тип **«Почта»**.
4. Придумайте название, например `Аналитика почты`.
5. Нажмите «Создать» — Яндекс покажет пароль из 16 символов.
6. **Скопируйте его сразу**: повторно он не показывается.
7. Вставьте этот пароль в файл `.env` в поле `YANDEX_APP_PASSWORD`.

Пароль приложения даёт доступ только к почте и может быть отозван в любой момент
в том же разделе.

## 7. Настройка файла .env

Скопируйте `.env.example` в `.env` (при первом запуске `start.bat` сделает это сам)
и заполните:

```env
YANDEX_IMAP_HOST=imap.yandex.ru
YANDEX_IMAP_PORT=993
YANDEX_EMAIL=sales@mycompany.ru
YANDEX_APP_PASSWORD=шестнадцатьсимволов

OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini

DATABASE_URL=sqlite:///./data/mail_assistant.db

DEMO_MODE=false
AI_ENABLED=true
READ_ONLY_MODE=true

CORPORATE_DOMAINS=mycompany.ru
```

**Важно:**

* Файл `.env` не попадает в git — он указан в `.gitignore`.
* Пароли и ключи не сохраняются в базу данных и не пишутся в логи.
* `READ_ONLY_MODE` изменить нельзя: программа принудительно работает только на чтение.
* `CORPORATE_DOMAINS` — домены вашей компании. По ним программа отличает письма
  сотрудников от писем клиентов. Их также можно указать в разделе «Настройки».

## 8. Настройка OpenAI API

AI-анализ не обязателен: без него программа работает на встроенных правилах.

1. Зарегистрируйтесь на https://platform.openai.com
2. Пополните баланс (анализ одной цепочки стоит доли цента).
3. Создайте ключ в разделе **API keys**.
4. Вставьте ключ в `.env` в поле `OPENAI_API_KEY`.
5. Модель по умолчанию — `gpt-4o-mini` (дешёвая и достаточная для этой задачи).

**Контроль расходов:**

* Одна и та же цепочка не анализируется повторно — результат кэшируется по хешу
  содержимого и обновляется только при появлении нового письма.
* В настройках задаётся максимум цепочек за один прогон (по умолчанию 50).
* Расход токенов виден в разделе «Настройки».
* Режим `AI_TEST_MODE=true` полностью отключает обращения к API.

> При включённом AI очищенный текст переписки передаётся в OpenAI. Если это
> недопустимо по правилам вашей компании, установите `AI_ENABLED=false`.

## 9. Первый запуск

**Windows — двойным щелчком:**

```
start.bat
```

Скрипт сам проверит Python, создаст виртуальное окружение, установит зависимости,
создаст `.env` и откроет интерфейс в браузере.

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # заполните файл
python run.py
```

Интерфейс откроется по адресу http://127.0.0.1:8000/

Остановка: `Ctrl+C` в окне программы или `stop.bat` (Windows).

## 10. Демонстрационный режим

Позволяет посмотреть работу программы без подключения к реальной почте.

```bash
python run.py --demo
```

или в интерфейсе: раздел **«Демо-режим» → «Загрузить демо-данные и проанализировать»**.

Загружаются 20 тестовых переписок, охватывающих ключевые ситуации: счёт отправлен,
ответили только ценой, письмо прочитано без ответа, менеджер запросил реквизиты,
предложен конкретный аналог, ответ «подберём», письмо с пятью задачами, повторное
обращение, рассылка и другие. Для каждого сценария указан ожидаемый результат, и на
странице видно, совпал ли фактический статус с ожидаемым.

Демо-письма формируются как настоящие MIME-сообщения и проходят весь конвейер
обработки, поэтому проверяется реальная логика программы. Демо-данные хранятся в
отдельном ящике `demo@example.local` и не смешиваются с рабочей почтой.

## 11. Синхронизация почты

1. Откройте раздел **«Настройки»**.
2. Нажмите **«Проверить подключение»** — программа сообщит, всё ли настроено.
3. Нажмите **«Синхронизировать … и проанализировать»**.

Что происходит при синхронизации:

* программа получает список папок и запоминает его;
* по умолчанию анализируются «Входящие» и «Отправленные» (набор папок настраивается);
* письма читаются командой `BODY.PEEK` — **флаг «прочитано» не меняется**;
* папки открываются в режиме `EXAMINE` — состояние ящика не изменяется;
* уже загруженные письма пропускаются (проверка по `Message-ID` и хешу содержимого);
* повреждённое письмо не останавливает синхронизацию — ошибка попадает в журнал.

Журнал всех синхронизаций с числом писем и ошибками виден внизу страницы «Настройки».

## 12. Запуск анализа

Анализ можно запустить:

* кнопкой **«Запустить анализ»** на главной панели;
* кнопкой **«Проанализировать заново»** в карточке конкретного обращения;
* автоматически сразу после синхронизации.

Анализ выполняется в два слоя:

1. **Технический (без AI)** — есть ли ответ, кто написал последним, есть ли вложения,
   прочитано ли письмо, сколько времени прошло (фактического и рабочего), нарушен ли срок.
2. **Смысловой (AI или встроенные правила)** — какие задачи поставил клиент и получил
   ли он по каждой из них результат.

Если OpenAI недоступен или отключён, работает встроенный анализатор на правилах —
программа не остаётся без результата.

## 13. Значение статусов

| Статус | Цвет | Когда присваивается |
|---|---|---|
| **CRITICAL** | красный | Письмо клиента требует ответа, но ответа нет; последнее сообщение от клиента осталось без реакции; клиент написал повторно; нарушен срок ответа |
| **INCOMPLETE** | оранжевый | Менеджер ответил, но запрос клиента не выполнен: нет счёта, нет КП, не названа цена, не указано наличие или срок, не рассчитана доставка |
| **WAITING_FOR_CLIENT** | жёлтый | Менеджер корректно запросил недостающие данные (реквизиты, количество, адрес, модель) или предложил вариант и ждёт решения клиента. **Это не ошибка менеджера** |
| **COMPLETED** | зелёный | Все задачи клиента выполнены, незакрытых вопросов нет |
| **NOT_RELEVANT** | серый | Реклама, массовая рассылка, автоматическое уведомление, спам |
| **NEEDS_REVIEW** | фиолетовый | Программа не уверена: непонятный запрос, неоднозначно собранная цепочка, невозможно проверить вложение |

Для каждого обращения всегда показывается **причина статуса** и **рекомендуемое действие**.
Любой статус можно исправить вручную в карточке обращения.

### Как проверяется выполнение

| Запрос клиента | Что считается выполнением | Что НЕ считается |
|---|---|---|
| Счёт | вложение-счёт (PDF/XLS/DOC с «счет», «invoice», «bill» в имени), ссылка на счёт или явное «счёт направлен» | сообщение цены, «выставим позже» |
| Коммерческое предложение | вложение КП или явное «КП направлено» | «подготовим КП» |
| Цена | конкретная сумма с валютой | «уточняем», «цена договорная» |
| Наличие | «в наличии», «нет в наличии», «под заказ», «ожидается», количество на складе | «посмотрим по складу» |
| Срок поставки | конкретный срок, дата, диапазон дней | «скоро», «в ближайшее время» |
| Доставка | стоимость, способ, транспортная компания или срок доставки | «доставим» |
| Аналог | конкретная модель или артикул | «можем подобрать аналог», «подберём» |
| Документы | вложения или рабочая ссылка | обещание прислать |

## 14. Экспорт отчёта

**Excel** — кнопка «Excel» на странице отчёта или `/export/excel?day=ГГГГ-ММ-ДД`.
Листы: Сводка, Критические, Запрос не выполнен, Все обращения, По менеджерам,
По типам запросов.

**HTML** — кнопка «HTML» или `/export/html?day=ГГГГ-ММ-ДД`. Готовый файл для
отправки руководителю или печати.

## 15. Решение частых ошибок

**«Не удалось войти в почтовый ящик»**
Используется основной пароль вместо пароля приложения, либо в Яндекс.Почте не
включён доступ по IMAP, либо адрес указан без домена. См. разделы 5 и 6.

**«Не удалось подключиться к imap.yandex.ru:993»**
Нет интернета, либо порт 993 закрыт корпоративным брандмауэром или антивирусом.
Проверьте соединение и правила сети.

**«Превышено время ожидания»**
Медленное соединение или очень большой ящик. Уменьшите период синхронизации
(например, 3 дня) и максимум писем на папку в настройках.

**«Неверный OPENAI_API_KEY» / «Превышен лимит запросов»**
Проверьте ключ и баланс на platform.openai.com. Программа продолжит работать
на встроенных правилах; отключить AI можно в настройках.

**Письма загрузились, но все считаются входящими**
Не заданы корпоративные домены. Укажите их в «Настройки → Корпоративные домены»
и запустите анализ заново.

**Клиентские письма попадают в «Не относится к клиентам»**
Отправитель похож на автоматический (например, `info@…` с адреса службы доставки).
Уберите нужный адрес или домен из списка исключений в настройках.

**Порт 8000 занят**
Измените `APP_PORT` в `.env` или запустите `python run.py --port 8080`.

**Программа не запускается после обновления**
Выполните `update.bat` — он применит миграции базы. Резервная копия базы
создаётся автоматически в папку `backup`.

**Ничего не отображается на главной панели**
Проверьте выбранную дату (стрелки «←» и «→» вверху) и то, что анализ был запущен.

## 16. Безопасность

* **Режим только для чтения.** Отправка, удаление, перемещение писем, изменение
  флагов и папок запрещены. Все операции записи вынесены в отдельный модуль
  `app/services/mail_actions.py` и отключены: попытка вызова приводит к ошибке.
  Это проверяется автоматическим тестом.
* **IMAP не изменяет состояние.** Папки открываются через `EXAMINE`, тела писем
  читаются через `BODY.PEEK` — флаг «прочитано» не выставляется.
* **Секреты не в коде и не в базе.** Пароль и API-ключ читаются только из `.env`.
  В базе хранится лишь ссылка на источник секрета (`env:YANDEX_APP_PASSWORD`),
  что позволит перейти на OAuth без переделки программы.
* **Логи не содержат** текстов писем, паролей, токенов, реквизитов и вложений.
  Записываются только идентификаторы, счётчики, коды ошибок и длительности.
  Логи ротируются (5 файлов по 5 МБ).
* **Вложения по умолчанию не сохраняются** на диск — хранятся только метаданные.
  При включённом сохранении имена файлов очищаются от путей, опасные расширения
  (`.exe`, `.bat`, `.js` и другие) не сохраняются, существующие файлы не
  перезаписываются, размер ограничен.
* **Всё работает локально.** Данные хранятся на вашем компьютере. Наружу уходит
  только очищенный текст переписки в OpenAI — и только если AI-анализ включён.

## 17. Резервное копирование базы

База данных — один файл: `data/mail_assistant.db`.

**Ручная копия:** остановите программу и скопируйте файл в надёжное место.

```bash
# Linux / macOS
cp data/mail_assistant.db backup/mail_assistant_$(date +%Y%m%d).db
```

```bat
rem Windows
copy data\mail_assistant.db backup\mail_assistant_%date%.db
```

**Автоматическая копия** создаётся при каждом запуске `update.bat` в папку `backup`.

**Восстановление:** остановите программу, скопируйте файл из `backup` обратно в
`data/mail_assistant.db`, запустите программу.

Вместе с базой имеет смысл сохранять файл `.env` (в защищённом месте — в нём пароли)
и папку `data/attachments`, если включено сохранение вложений.

## 18. Архитектура и структура проекта

Приложение построено слоями: конфигурация и инфраструктура → модели → сервисы →
веб-интерфейс. Логика анализа не зависит от способа получения писем, поэтому
демо-режим и реальная почта проходят один и тот же конвейер.

```
Почта (IMAP, только чтение)
        ↓  imap_client + sync_service
Письма в базе (Message, Attachment)
        ↓  threading_service — сборка цепочек
Обращения (Thread)
        ↓  rule_analyzer — технические признаки, время, SLA
        ↓  thread_context + text_cleaner — очищенный контекст
        ↓  ai_analyzer (OpenAI) или heuristic_analyzer (правила)
        ↓  validate_ai_result — защита от выдуманных выводов
Статус + задачи клиента (CustomerRequest, AnalysisResult)
        ↓  reports / export_excel / export_html
Панель, отчёты, выгрузки
```

### Модель данных

`MailAccount` (ящик) → `MailFolder` (папки) → `Message` (письма) → `Attachment`
(вложения). Письма объединяются в `Thread` (обращение), к которому относятся
`CustomerRequest` (задачи клиента), `AnalysisResult` (история анализа) и
`ManualReview` (ручные исправления). Настройки интерфейса хранятся в `AppSetting`,
журнал синхронизаций — в `SyncRun`.

### Как собираются цепочки

По убыванию надёжности: `Message-ID` / `In-Reply-To` / `References` →
точное совпадение нормализованной темы **вместе с** совпадением клиента и
близостью по времени (до 30 дней) → иначе создаётся новая цепочка.
Общие темы («Запрос», «Вопрос», «Счет») никогда не служат основанием для
объединения. Если цепочка собрана по теме, уверенность понижается и обращение
помечается как требующее проверки.

## 20. Ограничения первой версии

* **Точное время прочтения письма через IMAP недоступно.** Известно лишь, что
  письмо отмечено флагом «прочитано», и время его получения. Программа никогда
  не выдаёт время прочтения за факт.
* **Содержимое вложений не проверяется** — только имя файла, тип и размер.
  Файл считается счётом по названию и формату; при сомнении обращение помечается
  как требующее ручной проверки. Архитектура подготовлена для чтения PDF, DOCX,
  XLSX и TXT в следующих версиях.
* **AI может ошибаться.** Каждый вывод сопровождается цитатой из переписки и
  показателем уверенности; вывод без подтверждения автоматически отклоняется.
* **Объединение цепочек иногда неоднозначно** и требует ручной проверки.
* Программа не отправляет письма и не формирует счета.
* Интеграции с 1С нет.
* При включённом AI данные анализируются через внешний API OpenAI.
* Распознавание запросов настроено на русскоязычную B2B-переписку.

Эти ограничения также перечислены в интерфейсе, в разделе «Ограничения».
